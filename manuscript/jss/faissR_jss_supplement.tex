\section{Scope}

This supplement records the minimum additional information required to
interpret and reproduce the results in the article. It covers the software
environment, dataset dimensions, calibration grids, exactness and target
criteria, completed evidence, and aggregation rules. It does not report
unanalysed jobs or development-stage results.

The evaluated nearest-neighbor implementation was \pkg{faissR} 0.99.21 at
commit:

results are linked to the package commit and Singularity-image fingerprint.

The two package versions define separate experimental strata. No elapsed-time
ratio combines a 0.99.21 campaign call with a 0.99.25 controlled-comparison
call. Releases 0.99.22--0.99.25 added session backend precedence, restricted
the public metric surface to the three metrics analyzed here, refactored input
and route metadata, improved Bioconductor and Windows configuration, and added
the controlled-comparison infrastructure. The latter routes were independently
recall-audited against the archived exact references rather than assumed to be
performance-equivalent to 0.99.21. The exact boundaries and release-by-release
controls are in \path{experiment_version_boundaries.csv} and
\path{experiment_version_changes.csv}.

The ada partition contains several processor generations. Consequently, CPU
results are paired within compatible cells and summarized by dataset; no single
processor model is assigned to all CPU jobs. CUDA timing ends only after device
synchronization. The optional CUDA automatic policy is an experimental,
L40S-calibrated heuristic for cold full-self-search. It remains callable
elsewhere, but its metadata identify hardware extrapolation rather than a
universal optimum.

The installable source package supports functional FAISS CPU builds on Linux
and macOS and on Windows when FAISS is built with the Rtools compiler family.
It requires a C++20 compiler, Fortran, R/Rcpp headers, and FAISS headers and
libraries. Configuration searches \code{pkg-config}, standard prefixes,
\code{FAISS\_HOME}, and the documented CUDA/cuVS prefixes. NVIDIA libraries
are not needed for CPU-only use; setting the strict GPU feature variables makes
missing CUDA or cuVS fatal. Prebuilt Bioconductor/r-universe workers that lack a
compatible FAISS system library can produce diagnostic-only binaries, whereas
functional source installs require the external library. Native Windows GPU
deployment is not claimed; WSL2 follows the Linux CUDA instructions. The
package does not promise ABI compatibility across arbitrary external-library
upgrades. Its inter-package C-callable surface has a separate integer ABI
version, currently 1, which consumers must verify.

CUDA auto results record calibration and runtime device identities. A runtime
model other than the L40S, or an unidentified model, receives
\code{hardware\_extrapolated\_unvalidated} and a once-per-model session
warning; the static route is not silently replaced. The warning can be disabled
after inspection. Local \code{pilot} and \code{cache} tuning compare
parameters only within the explicit or resolved method. No public workflow in
this release constructs, versions, validates, installs, or invalidates a new
cross-method policy, so the bundled selector remains an experimental
L40S-informed heuristic on other systems and outside the cold full-self-search
workload.

All public Euclidean outputs are ordinary L2 distances. The exact-reference
audit compares provider outputs with absolute tolerance $10^{-5}$ and relative
tolerance $10^{-4}$, namely
$|a-b|\leq 10^{-5}+10^{-4}|b|$. These constants were frozen before analysis to
cover float32 rounding near zero and proportionally at larger distances; they
do not alter search results or recall targets. Native ties are ordered by
distance and then row identifier. Provider-specific boundary identifiers are
accepted only when exact rescoring satisfies the same distance rule.

FAISS/cuVS searches use float32 coordinates. R doubles are converted inside
the public call. Normalized float32 routes accumulate row means and squared
norms in double precision, then store transformed coordinates as float32;
native double routes transform in double precision. Every route rejects
\code{NA}, \code{NaN}, and infinite values. The package's explicit
\code{nn\_metric\_preflight()} scan reports affected reference and query rows
before dispatch. CPU zero-normalized conventions and CUDA rejection are
therefore a documented backend-dependent contract, not identical behavior.

\section{Public interface and object contract}

The primary search function \code{nn(data, points, k, exclude\_self, backend,
method, metric, tuning, target\_recall, output, n\_threads)} returns a
\class{faissR\_nn} list. Its \code{indices} and \code{distances} components
have dimension $m\times k$. Host identifiers use R's integer type and one-based
row numbering. Distances are double by default, optional float32 through
\pkg{float}, sorted in smaller-is-better order, and accompanied by
\code{distance\_is\_metric}, \code{distance\_semantics},
\code{distance\_comparable\_across\_queries}, and
\code{distance\_order}. Request metadata distinguish \code{requested\_method}
and \code{requested\_backend} from \code{backend\_used} and
\code{resolved\_backend}; provider parameters and auto-selection evidence are
nested rather than inferred from the public method label.

CPU \code{method = "auto"} is explicitly labelled with
\path{auto_policy_status=calibration_informed_not_independently_validated} and
\path{auto_policy_evidence_scope=cpu_static_policy_experimental}. The label is
printed and retained in
the nested auto-selection record. CUDA auto carries its narrower evaluated
scope, \code{cuda\_cold\_full\_self\_search}. The numeric
\code{target\_recall} argument accepts only 0.90, 0.95, and 0.99; all other
values error, with no rounding or interpolation.

The exhaustive names are dispatch policies. On CPU, \code{exact},
\code{flat}, and \code{bruteforce} resolve to FAISS Flat. On CUDA,
\code{exact} prefers FAISS GPU Flat and otherwise direct cuVS brute force;
\code{flat} requires FAISS GPU Flat; and \code{bruteforce} prefers direct cuVS
and otherwise uses FAISS GPU Flat. The concrete metric-specific
\code{backend\_used} value is authoritative for an installed capability set.

The public metrics are Euclidean, cosine, and correlation. All listed methods
support all three metrics on their supported backend; CAGRA is CUDA-only and
the exact grid route is restricted to two or three dimensions. Runtime support
can be narrower because it depends on the linked FAISS/CUDA/cuVS build.
\code{nn\_capabilities(runtime = TRUE)} is the authoritative machine-readable
matrix and \code{backend\_info()} reports provider availability. An explicit
unsupported method, metric, or device fails before dispatch and never silently
changes method, metric, or device. \code{nn\_metric\_preflight()} separately
reports one-based affected rows and the backend action for non-finite,
zero-vector cosine, and constant-row correlation input.

Inputs are dense numeric matrices, data frames, or optional \pkg{float}
matrices, with observations in rows. Sparse matrices, \pkg{DelayedArray}
objects, and file-backed matrices have no native search adapter. Because
matrix-like inputs pass through \code{as.matrix}, they may be eagerly
materialized or densified; callers should make this conversion explicit. For a
conventional R double matrix, direct FAISS/cuVS routes allocate a contiguous
float32 payload of approximately $4np$ bytes while the original $8np$-byte R
payload remains live; index, workspace, query, and result allocations are
additional. Direct \pkg{float} adapters avoid the numeric conversion for
supported routes, although a layout copy may remain and is recorded in
\code{input\_layout} and \code{input\_owns\_data}.

Duplicate rows are not collapsed: identifiers denote rows, and distinct rows
may have zero distance. For self-search, \code{exclude\_self = TRUE} removes
the identifier equal to the query row. Compiled routes request enough
candidates to return $k$ non-self identifiers; if an approximate result omitted
the query identifier, no unrelated neighbor is removed. Package-owned exact
scorers order equal distances by identifier; external providers may choose a
different member at a tied boundary, which is handled by the exactness and
recall audits. Every backend rejects \code{NA}, \code{NaN}, and infinite
values. CPU cosine and correlation apply the documented finite convention to
undefined normalized rows, whereas explicit CUDA routes reject them rather
than performing CPU repair.

\code{knn()} without test data returns a \class{faissR\_knn\_model}; with test
data it immediately returns predictions. \code{predict()} reuses session-local
CPU FAISS Flat, HNSW, IVF, or IVF-PQ indexes when the route is compatible and
records \code{query\_source = "fitted\_index"}; otherwise it rebuilds the same
requested route. There is no public manual destroy operation. The external
pointer is released by its finalizer after its owner becomes unreachable.
\code{saveRDS()} preserves model specification, training data, and response,
but not a portable native index; a reloaded model detects the stale pointer and
rebuilds before prediction. Native index serialization is not otherwise
supported.

\code{nn\_gpu()} returns a \class{faissR\_gpu\_knn} with an owning handle and
non-owning device pointers. The buffers are column-major $m\times k$, with
one-based int32 identifiers and float32 distances, and report
\code{result\_residency = "cuda"} and
\code{device\_to\_host\_result\_copies = 0}. The producer synchronizes the
recorded device before return but exports no stream or provider resource.
Consumers retain the owner, select the recorded device, synchronize their own
work before release, and never free the child pointers. The object is
same-process and same-device only; serialization and CUDA IPC are unsupported.
\code{gpu\_knn\_to\_host()} explicitly copies both buffers and leaves the
resident owner valid until finalization.

\code{fast\_kmeans()} returns \class{faissR\_kmeans}, compatible with the
principal components of \class{kmeans}: integer assignments, centers,
within-cluster sums of squares, sizes, iteration/convergence fields, and
backend/tuning metadata. \code{knn()}, \code{predict()}, and
\code{fast\_kmeans()} are documented and executable secondary interfaces, but
the article makes no comparative predictive-accuracy or clustering-quality
claim for them.

Automatic method and parameter lookups are deterministic. Package-owned graph
routes use \code{options(faissR.approx\_knn\_seed = 4L)} by default and record
their seed backend and route parameters. Exact and grid routes are
deterministic apart from provider tie ordering. FAISS HNSW/IVF/PQ and cuVS
graph construction can include provider-controlled random or parallel stages;
GPU kernels are not promised to be bitwise reproducible across drivers,
devices, or provider releases. Procedural reproduction therefore archives the
input fingerprint, package and experiment commit, requested method/backend,
\code{backend\_used}, metric, $k$, requested recall tier, full route/tuning
parameters, seed option, thread controls, provider versions, and hardware
fingerprint.

The selector does not currently accept a memory budget, build or latency
deadline, or \code{allow\_exhaustive = FALSE} constraint. It also has no
resource-model-based abstention. Users impose such constraints by selecting an
explicit route; a future constrained selector requires peak-memory and latency
models validated on the target hardware.

\section{Package-owned experimental graph refinements}

The native implementations behind \code{nsg\_style},
\code{vamana\_style}, and CPU \code{nndescent\_style} are experimental
self-KNN candidate-refinement procedures. They are not canonical
reimplementations. Returned objects identify the scope as
\path{package_owned_style_implementation}, set
\path{implementation_status} to \code{experimental}, set the
\path{experimental} flag to \code{TRUE}, and set
\path{canonical_reimplementation} to \code{FALSE}. CUDA
\code{nndescent\_style} can instead resolve to direct cuVS NN-descent and is
then labeled as an external-provider route. Cosine input is row-normalized;
correlation input is row-centered and row-normalized; both are refined as
Euclidean candidates before documented distances are restored.

\paragraph{NSG-derived refinement.}
Given an ordered seed-neighbor matrix $S$ with width $s$, output degree $r$,
and protected prefix $k$:
\begin{enumerate}
\item For each query row $q$, remove duplicates and the self identifier from
      $S_q$, preserving order, and retain the first $k$ candidates.
\item For every later candidate $v$, reject $v$ when a retained $u$ satisfies
      $d(u,v)<d(q,v)$; otherwise retain $v$, up to degree $r$.
\item Fill unoccupied degree slots from the original ordered candidates and
      exactly rescore the retained row candidates; return the closest $k$.
\end{enumerate}
The implementation borrows a relative-neighborhood pruning test. It omits
canonical NSG navigation, medoid entry selection, connectivity repair, and
graph traversal.

\paragraph{Vamana-derived refinement.}
This route uses the same ordered seed and exact row-rescoring framework, but
applies robust pruning: candidate $v$ is rejected when a retained $u$ satisfies
$\alpha d(u,v)\leq d(q,v)$. It omits canonical Vamana's randomized incremental
insertion, medoid graph search, reciprocal edge updates, reachability repair,
and disk-oriented representation.

\paragraph{NN-descent-derived refinement.}
For pool size $L$, candidate cap $C$, projection count $P$, iteration count
$t$, and integer seed:
\begin{enumerate}
\item Generate $P$ seeded Gaussian directions, sort projected rows with an
      identifier tie break, and collect neighbors from bounded projection
      windows. Seeded random and then sequential fill complete short pools.
\item At every fixed iteration, freeze the previous graph, construct bounded
      reverse-neighbor lists, and evaluate capped neighbor-of-neighbor and
      reverse-neighbor joins for each row.
\item Retain the best $L$ candidates after each iteration and return the first
      $k$ after the final exact candidate scoring.
\end{enumerate}
The implementation omits canonical NN-descent new/old flags, sampled local
joins, and convergence-based stopping. For fixed input, seed, parameters, and
seed provider, package-owned stages use deterministic ordering. An external
seed provider can retain its documented floating-point or threading variation.

For approximate calibration candidate $s$, eligibility requires mean query
recall $R_s\geq\tau$. Each candidate was timed once and the eligible candidate
with minimum elapsed time was selected, with deterministic tie-breaking by
higher recall and candidate identifier. During independent validation, target
attainment requires mean query recall $R_{sr}\geq\tau$ in every prespecified
replicate $r$. Minimum query recall is diagnostic and does not define
attainment. Exact-audited candidates form a separate eligibility class.

For the three public metrics, 6,453 of 6,804 planned calibration operating
points produced a completed recommendation. The 351 unavailable points were
318 CPU and 33 CUDA cells and were excluded rather than imputed. Among completed
points, 1,728 were exact-audited. Of 4,725 approximate points, 3,653 met the
target and 1,072 did not. The latter remain visible in policy evidence as
\code{best\_recall\_below\_target} and cannot be described as target attaining.

\section{Validation and aggregation}

Validation used two query seeds and three timing repeats for each dataset,
metric, $k$, and target. Calibration and validation query samples were
independent, but both were drawn from the same named dataset. The query seeds
are the independent recall units; timing repeats reuse a seed's queries and
measure runtime dispersion rather than additional recall evidence. Approximate
recall is tie-aware: identifiers strictly inside the archived $k$th boundary
must match, while unmatched candidates are exactly rescored and can receive
credit at a tied boundary within tolerance. Boundary credit is capped by the
number of boundary slots. For each seed, 1,000 deterministic query-level
bootstrap resamples provide a one-sided 95\% lower confidence bound for mean
tie-aware recall. A validation cell passes only when every seed completes and
its lower bound is at least the requested target. Identifier-overlap and
tie-aware point estimates, lower bounds, boundary-substitution frequencies,
and minimum query recall remain in the machine-readable outputs.
Exact-audited cells are evaluated by exhaustive-reference identity or
tie-equivalent distances and are not reclassified by approximate recall.

A separate backend-specific leave-one-dataset-out analysis removed every row associated
with the held-out named dataset before selecting a method family. It used the
same prespecified shape group when available and otherwise the three nearest
training datasets in $\log(n)$--$\log(p)$ space. The held-out dataset was used
only for evaluation. The package's compiled \texttt{auto} result was reported
separately because that policy summarizes the full calibration collection and
is therefore not independent LOODO evidence. CPU \texttt{auto} was not
completely evaluated in the version-pinned campaign; the CPU LOODO result is a
cross-fitted reconstruction from explicit routes, not installed-policy
validation.

The complete independent-query CUDA set included automatic selection, explicit exact
Flat, explicit brute force, and CAGRA for all nine datasets and three metrics.
Each route contributed 1,944 successful rows. The complete CPU faissR HNSW set
contained 1,944 successful rows. The separate-job external HNSW archive covered
Euclidean and cosine distance on seven datasets. It is retained for execution
accounting but is not used for primary CPU speed ratios because routes were not
coexecuted on the same node.

The controlled CPU HNSW experiment fixes dataset, $k$, and comparator within a
single Slurm array task. \pkg{faissR} and either \pkg{BiocNeighbors} or
\pkg{RcppHNSW} run on the same node and allocation. The initial route is
randomized reproducibly within each validation seed and alternated over five
repetitions. Each route repetition runs in an isolated worker after an untimed
128-row warm-up. Both routes receive the same double matrix. The experiment
reports end-to-end cold-call time, reusable-index build time, and fitted-index
query time separately during validation. The submitted quantitative provider
comparison uses only the cold-call phase. Build and fitted-query ratios remain
ineligible until both routes pass the corresponding fitted-query recall audit;
fitted-index reuse is demonstrated by the executable API example instead. For
every eligible phase, the ratio is
$T_{\mathrm{comparator}}/T_{\mathrm{faissR}}$; values above one favor
\pkg{faissR}. The audit retains failures and timeouts and rejects any pair that
does not verify a common hostname, allocation, and opposing route positions.
Recall-equivalent summaries require both routes to attain mean recall at least
0.99 in each included validation replicate.

The comparator settings were fixed before execution:
\pkg{BiocNeighbors} used \code{nlinks = 16},
\code{ef.construction = 200}, and \code{ef.search = max(50, 3k)};
\pkg{RcppHNSW} used the corresponding \code{M = 16},
\code{ef\_construction = 200}, and \code{ef = max(50, 3k)}. Thus, these are
prespecified-configuration comparisons rather than provider-optimal Pareto
comparisons.

An independently tuned HNSW extension evaluates recall--time Pareto curves for
each provider. It varies search effort at every dataset--$k$ cell and varies
construction effort at $k=30$. The fastest configuration attaining mean recall
of at least 0.99 in all three calibration repetitions is selected separately
for each provider and evaluated over five repetitions on independent queries.
Validation records cold-call, direct index-build, and fitted-query times as
separate measured phases. Fitted queries request $k+1$ neighbors and remove the
known source row before recall is calculated. No fitted ratio enters the paper
unless both providers attain the target in every validation repetition.

Both routes received the same R double matrix. \pkg{faissR} converted its input
to the float32 representation required by FAISS inside the timed public call;
the comparator APIs' internal precision was not instrumented and is therefore
not asserted. Provider-returned neighbor order was retained. Each route
requested $k+1$ neighbors and removed the query's identical training row inside
the timer; \pkg{faissR} performed this in compiled code, whereas the comparator
wrapper performed it in R. These choices measure end-to-end user-visible API
cost, not kernel-only search cost.

Twelve threads were requested through each public API and through
\code{OMP\_NUM\_THREADS}, \code{OPENBLAS\_NUM\_THREADS}, and
\code{MKL\_NUM\_THREADS}. The completed run did not retain CPU affinity or
sample active thread use. Accordingly, the article reports requested threads
and same-node coexecution but makes no claim that providers used an identical
number of active workers. The independently tuned Pareto protocol records the
Slurm allocation, Linux affinity mask, thread-control variables, and observed
process thread counts before and after each call.

\section{Reusable indexes and GPU-resident interoperability}

The query-workload experiment evaluates explicit query batches of 1, 32, and
1,024 rows on five datasets, with full self-search on the smaller datasets.
The fitted-index cache is cleared before the first call. Subsequent identical
queries record whether the persistent index was reused. For each method, the
audit reports cold time, repeated-query time, the explicit construction
estimate $\max(0,T_{\mathrm{cold}}-T_{\mathrm{warm}})$, amortized totals for
1, 10, and 100 batches, and the smallest batch count satisfying
\[
T_{\mathrm{cold,method}}+(A-1)T_{\mathrm{warm,method}}
\leq A T_{\mathrm{cold,Flat}}.
\]
Direct HNSW construction and fitted-query times are additionally measured in
the independently tuned provider experiment rather than inferred by
subtraction. The resident-set increase across construction is an empirical
index-memory estimate; the proglang{R} object size is reported separately
because it excludes native storage owned through an external pointer. Index
external pointers are session-local and have no supported
portable serialization; consequently, serialization cost is not reported.

The GPU-residency experiment uses 15 isolated cells: five datasets crossed
with query batches of 1, 32, and up to 1,024 rows. A minimal downstream package
includes \code{faissR\_api.h}, verifies ABI version 1, obtains
\code{faissR\_nn\_cuda\_tuned\_gpu\_call} with \code{R\_GetCCallable}, and
launches a CUDA checksum kernel over both returned device buffers. Only two
checksum scalars are copied to the host. The alternate phase calls
\code{gpu\_knn\_to\_host()} and materializes both complete matrices. Five
repetitions alternate operation order and record search, consumer, and transfer
times separately. Device memory is sampled for the worker process with
\code{nvidia-smi}; host \code{VmHWM} is valid per cell because each cell has a
fresh process.

The owning \code{handle} external pointer releases both CUDA allocations in
its finalizer. \code{indices\_ptr} and \code{distances\_ptr} are non-owning,
column-major views. The producer synchronizes the recorded device before
return but exports no stream or FAISS/cuVS resource handle. A consumer must
select the recorded device, preserve the owner while any asynchronous work is
outstanding, and synchronize its own stream before release. The pointers are
same-process allocations, not CUDA IPC handles; serialization, another process,
or another device is unsupported. A consumer using a different provider
resource manager may access the buffers after this synchronized handoff but
does not share faissR's stream, allocator, or resource ownership.

All algorithmic CUDA comparisons in the main benchmark use \code{nn()}; every
route in those comparisons returns host-resident matrices. The
\code{nn\_gpu()} experiment is reported separately because comparing its resident
output directly with a host-resident route would combine search and transfer
contracts.

\section{Replication}

The submission material contains:
\begin{itemize}
\item the installable \pkg{faissR} source package and reference manual;
\item a package vignette and the executable practical CPU example;
\item a single commented article replication script and its HTML output;
\item a checksummed result snapshot, its SHA-256 ledger, and a pre-analysis checksum
  gate;
\item machine-readable reconstructions of all 15 article and supplementary
  tables, with a table checksum manifest;
\item software, container, dataset, and result fingerprints; and
\item a reduced CPU path that reproduces the interface example without a GPU.
\end{itemize}
The full CUDA evaluation requires a compatible NVIDIA GPU and the recorded
FAISS/cuVS build. Reanalysis of the checksummed output does not require a GPU. The
standalone script has three explicit modes: \code{compact} runs interface
examples on an ordinary CPU computer, \code{archive} verifies the checksummed
archive before extraction and recreates every reported table, and \code{all}
runs both. Any digest, schema, dataset-fingerprint, aggregation, or table-audit
failure stops execution. A successful run records archive verification,
per-table SHA-256 digests, and a fresh \code{sessionInfo.txt}.

\section{Interpretation}

The evaluation establishes the package contracts and characterizes
calibration-informed operating points on the tested data and hardware. The
returned evidence metadata makes the selected provider, parameters, and recall
status inspectable. When application-specific recall is critical, users can
additionally validate the selected route against an exact query subsample.
